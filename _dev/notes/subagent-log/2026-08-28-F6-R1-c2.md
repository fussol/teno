## 逐項查證

### 1. allowBackup 語意鏈 — ✅ 命中
一手 URL：https://developer.android.com/guide/topics/data/autobackup
- 「Apps that target Android 6.0 (API level 23) or higher **automatically participate** in Auto Backup. … set the boolean value android:allowBackup … **The default value is true, but we recommend explicitly setting the attribute** in your manifest」→ 計畫 §2③ 兩條引文逐字忠實；T3 釘「顯式且唯一」與官方建議形一致。
- 一手 URL：https://developer.android.com/guide/topics/manifest/application-element（allowBackup 條）：「If this attribute is set to "false", **no backup or restore of the application is ever performed**, disabling all cloud backups and device-to-device (D2D) transfers… **The default value of this attribute is "true"**」→ 屬性缺席＝默認 true 的 bug 事實（T0 釘）官方根據確立。

**Auto Backup 覆蓋目錄**（autobackup「Files that are backed up」全表，現行版＋web.archive 2022 版同文）：
- 包含：shared_prefs、getFilesDir()/getDir()、getDatabasePath()（含 SQLiteOpenHelper 產物）、getExternalFilesDir()；且「**By default, the system backs up almost all app data**」。
- 排除＝**封閉集**：getCacheDir()、getCodeCacheDir()、getNoBackupFilesDir() 三目錄。

**teno.db 落點一手查證（成功，超出預期）**：
- Tauri 源碼 dev 分支 `crates/tauri/mobile/android/src/main/java/app/tauri/PathPlugin.kt`：`getConfigDir → activity.dataDir.absolutePath`（即 `/data/user/0/com.teno.app`，非 cache/no_backup 任何一員）；`crates/tauri/src/path/android.rs:139 app_config_dir()` 直通該呼叫。
- 倉內消費端：drive_sync.rs:23-29/36-39（teno.db、drive_tokens.json、drive_creds.json 全部 `app_config_dir()`）、icon_android.rs:58 註解自證同源。
- **推定強度：高**。官方列舉四類雖未逐字點名「自訂子目錄」，但「almost all app data」＋排除集為封閉三目錄（.config 類自訂目錄非其一）⇒ 覆蓋為預設常態。且此推定**不影響修法正確性**：`allowBackup="false"` 是全局關閉（application-element 原文「no backup or restore … ever performed」），不論 teno.db 是否恰在列舉表內，修法均成立、保守方向正確。

### 2. D2D 殘洞原文（§2 ③b）— ✅ 忠實
一手 URL：autobackup 頁 ＋ https://developer.android.com/about/versions/12/behavior-changes-12
- autobackup 原文：「For apps targeting Android 12 (API level 31) or higher, **this behavior varies**. On devices from some device manufacturers, specifying android:allowBackup="false" **disables cloud-based backup and restore (such as Google Drive backups) but doesn't disable device-to-device transfers for the app**.」
- behavior-changes-12 原文：「On devices from some device manufacturers, specifying android:allowBackup="false" does disable backups to Google Drive, **but doesn't disable D2D transfers for the app**.」
- 計畫引文「doesn't disable device-to-device transfers for the app」**逐字命中**；「部分廠商」措辭限制照錄亦誠實（§5 風險條對「vary」的解读正確：雲端關閉是確定語意、vary 的是 D2D——與 application-element「you can disable cloud-based backup … **even if** your app targets API 31+」一致）。
- **F6-SR1 改派恰當性：恰當，非過度防衛**。官方明文 allowBackup=false 對 targetSdk31+ 部分廠商不停 D2D ⇒ 本機 D2D（Smart Switch）殘洞是官方承認的事實，非 PM 臆造；而堵法需 res/xml 新檔＝白名單外 ⇒ 依鐵律改派是正解。**保留意見見發現 F2**：官方把 dataExtractionRules 定位為 D2D 規則的正統機制（bc12「To specify rules for D2D transfers, you must use the new configuration」），但「behavior varies」語意未保證其在這些廠商裝置上必效——計畫「完全堵需 dataExtractionRules」一句略超出官方保證範圍。
- ③c 旁知識：autobackup 原文「Android doesn't treat the configuration of components as user data. If your app enables or disables specific components in the manifest while it is running, Auto Backup doesn't automatically save and restore the configuration.」→ 忠實，F4/F5 alias 態零動作成立。

### 3. MANAGE_EXTERNAL_STORAGE／All Files Access — ✅ 宣稱真，刪權無副作用
一手 URL：https://support.google.com/googleplay/android-developer/answer/10467955（「Use of All files access (MANAGE_EXTERNAL_STORAGE) permission」政策原文）
- 「This is only applicable to apps that **target Android 11 (API level 30) and declare** the MANAGE_EXTERNAL_STORAGE permission」→ targetSdk=36＋聲明在位 ⇒ 政策適用。
- 「**If your app does not require access to the MANAGE_EXTERNAL_STORAGE permission, you must remove it from your app's manifest in order to successfully meet the policy review requirements.**」→ 「声明未用」不是「審查機率問題」而是**政策明文必刪**；另有「your app shouldn't declare permissions that it doesn't need or use」＋「Apps that fail to meet policy requirements … may be removed from Google Play」。PM ①「上架違規面」定性成立且偏保守。
- 政策同時列 MediaStore/SAF 為合規替代 ⇒ TtsPlugin 僅 MediaStore.Downloads（實查 :255-266 insert 鏈）不需要 MANAGE，刪除正當。
- **刪權對 API≤29 副作用：無**。MANAGE 與 MediaStore 寫入無關（API≤28 需 WRITE_EXTERNAL_STORAGE——①b 保留 maxSdk=28 正確；API29+ scoped storage 免任何權限走 MediaStore.insert）。
- 零消費者复读：`git grep ee93ffa` 全倉 MANAGE/isExternalStorageManager/getExternalStorageDirectory 僅 manifest:5 ＋兩份 _dev 筆記命中，代碼零消費者確認。

### 4. cleartext 管轄範圍（②「不實」判定）— ✅ 判定正確
一手 URL：https://developer.android.com/guide/topics/manifest/application-element（usesCleartextTraffic 條）
- 原文：「When the attribute is set to "false", **platform components, for example, HTTP and FTP stacks, DownloadManager, and MediaPlayer, refuse the app's requests** to use cleartext traffic. **Third-party libraries are strongly encouraged to honor this setting** as well.」→ 管制對象＝**平台元件（Java 棧）**，對非平台程式庫僅「encouraged to honor」（自願性）。
- https://developer.android.com/training/articles/security-config：開關語意經 **NetworkSecurityPolicy.isCleartextTrafficPermitted()**（Java API）消費——不调用該 API 的實作（Rust raw socket）在管轄外。
- 代碼复读：api.js:11-15 fetchLLM/fetchGet 皆 `invoke('fetch_llm'/'fetch_get')` → lib.rs:278/:343 **ureq**（spawn_blocking raw socket）；JS 直連 fetch 僅 https 外部 API＋store.js:595 相對路徑 same-origin——**WebView 零 localhost 明文消費者**確認。舊 curl-binary 態（F12）同理在管轄外。「release cleartext 擋 localhost LLM」**不實判定成立**。
- 附註：同條官方新文「This attribute is getting deprecated and will be ignored for apps targeting API levels 38 and above. Specify a Network Security Configuration…」→ T4/T5 登記釘保留 placeholder 鏈在 targetSdk 36 下仍有效；未來 targetSdk38+ 時 placeholder 對 release 變 dead（届时 debug devUrl 亦需 NC，非本輪範圍，順手登記）。
