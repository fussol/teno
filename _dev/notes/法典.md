## 第二章 憲法（10 條）

| # | 條文 |
|---|---|
| 1 | **無文件不送審** — 送審前 `_dev/notes/<bug>-fix-plan.md` 必須存在（Bug 定義 / root cause / 修法(檔名:行號) / 驗證 / 風險），違反該輪作廢 |
| 2 | **v1 窮舉消費者清單** — 涉及 token/變數值改變的 bug，v1 附完整 grep 清單＋三形態（template / inline style / JS setter） |
| 3 | **計算模型明訂** — 量化方式（float / 8-bit）、合成模型（sRGB / 線性、文字是否同受 opacity）、測試區間寫死 |
| 4 | **✅ 必須附實測證據**；委員間數據分歧先定比較基準再裁決 |
| 5 | **送審後版本凍結** — 修正一律升版並記錄審查歷程 |
| 6 | **範圍外自動進追蹤** — 計畫書「範圍外」清單自動建追蹤項 |
| 7 | **可選項必須定案** — 每項明確做 / 不做＋理由 |
| 8 | **過審後動工 checklist** — 每個修法點對應驗證方式，逐項勾選 |
| 9 | **動工前 git status 分離非本次改動** — 非本次 bug 的改動先分離，commit 前確認 diff 只含本次檔案 |
| 10 | **修補式方案連續 2 輪同類 edge 被退 → 重估替代結構**（如 id-keyed map），不繼續打補丁 |

## 第三章 法律（6 條）

| # | 條文 |
|---|---|
| 1 | 審查每輪 **3 名委員**；上限 **10 輪**（過就過，非必到上限）。**簡單 bug 可降為 1 名委員**（總統依 scope/非共享檔/低風險判定，2026-08-27 元首令） |
| 2 | **首相任務 = 一顆 bug 一任務** — 任何 bug 不與其他 bug 合併成單一 subagent 任務；同序列以「一顆完成 → 回報 → 總統再派下一顆」進行 |
| 3 | **殘局交接** — 首相達迭代上限或中斷時：中間產物先寫入磁碟；summary 固定列出「已完成 / 未完成步驟（含精確下一步命令）」；**禁止偽造驗證結果** |
| 4 | **驗證工具先行實跑** — 計畫書送審時驗證命令必須已實跑（或明確標註「工具未完成，驗證無效」）；委員有權實際執行驗證命令；工具跑不過＝該輪驗證無效 |
| 5 | **回報格式五欄** — 首相回報固定：commit hash / 審查輪數（幾輪幾人次）/ 驗證命令＋輸出摘要 / 計畫書路徑 / 未完成事項；總統收到後必須 git log＋工作區檢查核對 |
| 6 | **波次基線統一** — 每波並行開始前總統確認並廣播 git 基線（HEAD hash＋已知未 commit 舊改動清單）；首相發現基線外改動＝他首相進行中，不碰、不 add、不 commit |
| 7 | **subagent 限定 Hermes** — 所有 subagent（首相/委員/技術官僚/任何 delegate）一律以 Hermes delegate 執行；**opencode 及其他外部 CLI agent 一律禁用**，不得擔任委員、顧問或任何角色 |
| 8 | **subagent 紀錄 md 落盤** — 每個 subagent 任務完成後，其產出必须以 Markdown 存檔至 `_dev/notes/subagent-log/`（檔名含日期＋任務名）；內容至少涵蓋：任務目標、裁決/結論＋理由、驗證命令與實際輸出、未完成事項。無 md 紀錄之任務視為未完成 |
| 9 | **單一 bug 帳簿**（2026-08-30 元首令）— 全專案 bug 狀態唯一登記於 `_dev/notes/BUG-LEDGER.md`。①新發現 bug 一律先登帳簿再派工，禁止只存在於任務書/對話/記憶中的隱形 bug；②帳簿狀態四態：⬜未派工 / 📋有計畫書 / 🔧派工中 / ✅已修（`fix: <ID>` commit 為準）；③舊清單（bug-audit / BUGHUNT-TODO / scope-requests 佇列段）一律降為歷史存檔，不得再各自新增待修項；④每波收尾總統核帳：`git log --grep 'fix: <ID>'` 對拍帳簿，帳實不符即治理事件 |

## 版本制定規範（2026-08-28 元首令 v2，取代原「一 commit 一版本」；元首核准改制）

1. **一結案一版本**：bug 結案 commit → `./tools/version.sh patch`；功能完整落地（最後一顆）→ minor。功能中間顆、docs/test/審查/計畫書/tools/驗證腳本免升。
2. **版本語意**：`major.minor.patch`（major=破壞相容／minor=新功能／patch=修 bug）。FSRS 權重/排程語意變更 → minor 以上。
3. **升版唯一路徑 `tools/version.sh`**：機械寫齊 `package.json`＋`src-tauri/tauri.conf.json`＋`Cargo.toml` 三檔並自驗。手改單檔＝指紋分裂（2026-08-28 實錘病根：舊版讀 Cargo 舊值 sed tauri.conf 靜默跳過，三檔漂移 5.1.19/5.1.19/5.1.18 無人察覺）。
4. **指紋一致性＝機械閘**：`.githooks/commit-msg`（core.hooksPath，入 repo 追蹤）——code 路徑變更的 commit 必須 staged 三指紋檔齊全、三檔全等、版本有升，否則拒絕 commit。巡檢 `node tools/verify-version-sync.mjs`（源三檔全等＋live DB 指紋對拍，併入每波回歸清單）。派生指紋（UI 關於頁、`PRAGMA user_version`、`db_from_version`/`db_from_commit`、Android versionName）一律溯源至 package.json，不另設手動源頭。
5. **每個版本綁定 commit hash**：打包 build 前將當下 `git rev-parse HEAD` 寫入 `package.json.buildHash`；app 開機自動寫 DB `PRAGMA user_version`（major*1e6+minor*1e3+patch）+ `settings.db_from_version`（字串）+ `settings.db_from_commit`（該版本對應 commit hash）。
6. **DB 分析定版**：任何分析 DB 前，先讀 `PRAGMA user_version`＋`db_from_commit` 確認版本邊界，不再用 reviewed_at 格式猜。
7. **只升不降**：DB user_version 只寫更高值，降級 app 開舊 DB 不覆寫既有版本指紋。
8. **十 tap 例外**：devMode（設定→關於連點）等非發布流程不要求升版，但正式 build/APK 必須。
9. **逃生門**：commit message 帶 `[skip-version]` 明示繞過（留可 grep 紀錄，需總統同意）；`--no-verify` 繞過＝治理事件。
