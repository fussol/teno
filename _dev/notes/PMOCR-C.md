# PM-OCR 階段C任務：資料流、DB 整合與分期計畫（行級）

你是 Teno 專案的 PM-OCR。功能：**OCR 辨識字 — 辨識出的單字文字送入現有「新增單字」流程入庫**。
下方快照含：src/lib/api.js 全文、src/lib/db.js 全文、src/lib/store.js 的 addWord 節錄、src-tauri/src/lib.rs command 簽名節錄、capabilities。

## 鐵律
- 你沒有檔案/終端工具，只能輸出 markdown。**現況描述必須引用快照原文**。偽代碼要標明。
- 每個修改點：檔案+函式+原文錨點（前後2-3行）、完整可貼代碼、後果（哪些現有呼叫端受影響 — 列舉你從快照看到的呼叫位置）、回退方式。

## 交付（最終回覆直接輸出）
### 第5章 資料流與整合
辨識文字 → 單字候選 → 送入現有新增單字路徑（store.addWord / 或更合適的現成入口 — 從快照判定哪條路徑最正確，說明理由）。重複單字怎麼處理（查快照現狀行為）。批量新增 vs 逐筆新增的事務考量（saveWordsInTx 現狀）。
### 第6章 逐檔案修改清單
P1 範圍：每個檔案的新增/修改完整代碼區塊 + 插入錨點。Tauri 端需要的話：lib.rs 新 command / plugin 註冊 / capabilities 權限（camera、fs）各給完整代碼。Android 端若走原生 plugin：獨立 crate 骨架。
### 第7章 驗證計畫
每個修改點：測試步驟+預期結果+負控制（故意餵壞圖/空圖/多語言混排）。手機與電腦分列。
### 第8章 分期實施
P1 最小可用（電腦端 Tesseract.js 全鏈路）→ P2 手機端引擎 → P3 增值（多字分割、自動查詞）。每期：交付物、工作量估計、可獨立驗證的驗收標準。
### 第9章 風險與範圍外
APK 體積、記憶體、離線模型下載、辨識準確率預期管理；明確登記本次不做的事。
